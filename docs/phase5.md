## 画面とグラフ（IB-001〜008）

- 最新4指標→成長グラフ→測定履歴入口の順。最新測定日の中で登録が新しい測定を初期表示し、同日の別測定へ切替可能。登録時刻と測定時刻を区別する。
- 体重・体脂肪率・筋肉量・BMIを表示。筋肉量は `筋肉量(kg)`、骨格筋量グラフは `骨格筋量(kg)` を参照し、相互に代用しない。
- 体重・骨格筋量・体脂肪率・体脂肪量・部位別筋肉量・InBody点数の6種類を切替。期間はPhase 4と共通の1か月・3か月・6か月・1年・全期間。
- 部位別は両腕／両脚の左右比較と体幹。正式な右腕／左腕／右脚／左脚／体幹筋肉量の列名で対応し、左右を入れ替えない。
- 測定1件につき指標ごとに1点、欠損値は点を省略し、0は描画。0件は空表示、1件は単一点。同日複数件も別点で保持する。
- 同日点の横方向のずらしは重なり回避のためだけに使い、測定時刻や測定順を推測しない。時刻が不明な測定を線で結んで前後関係を作らない。点のタップ／キーボード操作で日付・値・単位を確認でき、表でも全値を閲覧できる。
- 日付のみの測定日はタイムゾーン変換せず保持。期間の「今日」は利用者のタイムゾーンで求める。登録順の比較ではDBの小数秒も考慮する。

## CSVと44項目の保存（IB-009〜017）

- 右上のCSV選択からプレビューへ進み、測定日・各原項目・行と列のエラーを確認・修正してから正式保存する。
- UTF-8 BOM、CRLF/LF、引用符・エスケープされた引用符・カンマ・セル内改行、複数行に対応。空／重複ヘッダー、不足／未確認列、列数不一致、数値不正を明示する。ヘッダーはUnicodeの `²`・`°` と空白も保持して比較する。列番号だけに依存せず、正式列名で対応づける。
- 44項目すべてを `raw_fields` の1 JSONBオブジェクトへ保存。`-`・空欄はnull、原値の `0` は欠損に変換しない。CSVセルの有効な原表記（例：`70.00`）は文字列で保持し、数値として利用する際だけ解析する。したがってCSVの `0` は原値では文字列 `"0"`、グラフや計算では数値0となる。既存JSONの数値0も保持・対応する。
- `日付`・`測定機器` は数値列として解釈しない。機器IDの先頭0も保持する。他の確認済み42列は非欠損時に有限数値として検証する。
- `InBody-YYYYMMDD.csv`、`InBody-YYYYMMDD(1).csv` と同形式の番号接尾辞に対応。指数表記の日付 `2.0261E+13` は原文を保持し、日時へ復元しない。既定測定日はファイル名から取得し、各行で修正可能。
- 行の日付が明確なYYYY-MM-DD／YYYY/MM/DD／YYYYMMDDの場合だけ行別候補を利用する。それ以外はファイル名候補または手動入力にする。指数表記や未確認の日時形式を推測しない。
- 同じ測定日・全44項目一致は重複スキップ。同日異値は追加／特定測定の置換／スキップを明示選択する。未選択・置換対象未指定では書き込まない。同日同値の別実測を自動区別できない限界を画面に明記する。
- プレビューは正式データに含めない。正式保存はオンラインの成功応答と返却行を確認してから反映する。1行＝1測定＝1文のINSERT/UPDATEなので44項目が途中まで更新される状態を作らない。置換は指定IDのみを更新し、登録時刻を維持する。
- 複数行は行ごとに確定する。成功・スキップ・失敗を分け、失敗行と入力を残し、再試行時に成功済み行を再送しない。新規行のUUIDはプレビュー中固定し、応答不明後も既存同一行を再読して照合する。バッチ全体の一括ロールバックを保証する設計ではない。
- 1ファイル2MB・1000測定行まで。構文として壊れたCSVはファイル単位で修正を求める。列数や数値の行エラーは行別に保持し、正常行は保存可能。

## 履歴・編集・削除と保存（IB-018〜024）

測定日の新しい順で履歴を表示し、同日内は登録順で表示する。詳細は正式ヘッダー順の44項目と元ファイル・測定日・登録時刻を表示。編集は明示操作で開始し、測定日と全44項目を修正できる。数値検証、保存・キャンセル、未保存変更の破棄確認と離脱警告を備える。

編集・削除は所有者IDと対象UUIDを限定し、オンライン成功時だけ正式状態を更新する。削除は確認付き。最新削除後は次の最新測定へ自動で切替。4指標と全グラフは共通の測定リストから都度導出し、古い集計を残さない。

ユーザー別IndexedDBの `cache/inbody` はトレーニング・週間目標とは分離。通信失敗時は保存済みの表示を保持し、サーバー未確認と表示する。端末キャッシュ更新失敗はサーバー保存失敗と区別する。過去測定のオフライン正式編集・同期キューは追加しない。

InBodyのリポジトリは `inbody_records` だけを書き込み、トレーニングの記録・PR・週間目標は更新しない。OCR、InBody API、JSONバックアップは実装していない。

## 検証とテストデータ

単体試験は合成ヘッダーによるCSV構文の独立試験と、正式ヘッダー＋生成した架空測定値によるマッピング試験を分ける。部位別左右・筋肉量と骨格筋量・欠損・0・完全一致・期間・同日複数・数値エラー・途中失敗・保存応答・キャッシュ分離を確認する。

ユーザー添付の匿名化サンプルも作業環境内で実パーサーに通し、44列・1行・欠損14・ゼロ2・12指標対応・指数表記原文の保持・(1)付きファイル名採用を確認した。サンプル本体をGitに保存せず、計測値を検証ログへ出力していない。

ブラウザのローカル試験は実Chromium＋PGliteで、Supabase通信をすべてローカルDBへ転送する。実DB試験はA/Bの専用UUIDだけを台帳管理し、作成前に存在しないことを確認する。ブラウザからの更新・削除も所有者・台帳IDでガードする。

`/tmp/muscle-phase5-fixtures.json` にInBody、`/tmp/muscle-phase5-training-fixtures.json` にPR回帰用の専用記録IDを保存。削除はIDと所有者で限定し、削除後の再読で残存0件を確認する。異常終了時も台帳を手動で消さずcleanupを実行する。

```sh
npm run lint
```

## 既知の制約

- ユーザーから実ヘッダーと匿名化サンプルを受領したため、実CSV待ちによる列対応・正式取り込みの保留は解消した。
- 提供された実構造サンプルは1行・1形式。複数行や全項目入力、欠損・エラーの組み合わせは同じ正式ヘッダーに対する架空値で検証する。他機種・別エクスポート形式の互換性や、未提供の日時表記を保証しない。
- バッチは行単位保存。応答のみ喪失した場合はサーバーで確定済みの可能性があるため、結果不明のまま全体成功とは表示せず再読を案内する。
- 主に1端末の利用を前提とし、多端末による同一測定の同時編集の高度な競合解決はPhase 6の対象。
- 実機のタッチ・ソフトウェアキーボード、Safari/Firefox、大量データの性能は未検証。Chromiumのスマートフォン幅と既存回帰のデスクトップ幅を検証する。
