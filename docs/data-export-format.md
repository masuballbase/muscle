# JSONデータ出力 v1

OPEN-02はユーザーの承認により、サーバー保存済みデータと端末未同期セッション・メニュー下書きを両方含める。インポート・復元用の形式ではなく、版と確認状況を保持する参照用データである。

| フィールド | 意味 |
| --- | --- |
| schemaVersion | `muscle-data-export/1` |
| exportedAt | ファイル生成日時（ISO 8601、クライアント時計） |
| userId | 出力対象のログインユーザーID |
| scope | 対象8テーブル、端末未同期・下書きを含むこと、認証情報・復元機能を含まないこと |
| server.source | `server` |
| server.confirmation | `fresh`＝今回全件取得、`cached`＝過去の全件取得キャッシュ、`unavailable`＝利用可能な全件データなし |
| server.lastConfirmedAt | その全件データを取得確認した日時。取得不能ならnull。出力日時と混同しない |
| server.tables | 8テーブルの元ID・関連ID・値を保持した行配列。取得不能ならnullであり、空配列とは異なる |
| server.omittedColumns | 未知の列名の一覧。既知業務項目以外を無断で出力しない。現行実DBの8テーブルでは除外0を試験する |
| device.source | `device_indexeddb` |
| device.capturedAt | 同一IndexedDBトランザクションで端末内容を読み取った時刻 |
| device.sessions | 端末保存済みの未同期セッション。`source`・`syncStatus=pending`・`confirmation=not_confirmed`・`persistedAt`・`value`を保持 |
| device.menuDrafts | メニュー下書き。`syncStatus=draft_not_formal`。元の正式メニュースナップショット`base`も保持 |
| device.volatileInputIncluded | false。メモリだけに残った保存失敗入力を取得したと保証しない |
| device.volatileInputAtRisk | 出力開始時に端末保存失敗を検出したか |
| counts | サーバーのテーブル別件数、端末未同期・下書き件数、原44項目が揃わないInBody件数。取得不能のサーバー件数はnull |
| warnings | オフライン、欠損、未知項目除外、端末保存失敗、全体の同一時点を保証しないことなど |

対象テーブル：`exercises`、`menus`、`menu_items`、`sessions`、`session_exercises`、`workout_sets`、`weekly_goal_schedule`、`inbody_records`。論理削除済み種目も含む。`used_at`など既存の業務管理列も保持する。

サーバー行は`user_id`を照合する。端末はログインユーザーとUserStoreのIDが一致する場合だけ読み取る。セッション・種目別記録・セットのIDと関連付けを維持し、同一IDのサーバー版と端末版は別区分のまま残す。未同期の新しいrevisionを古いサーバー版で上書きしない。同期の基準スナップショット・未確認の送信候補も、既知の業務項目だけを選んで端末セッションに保持する。

InBodyは正式44ヘッダーの原値をそのまま出力する。nullはnull、原文字列の0は文字列`"0"`、DBに数値0が保存されている場合は数値0。原項目が不足している古い行は、架空の値で44項目に補完せず件数と警告を表示する。未知の原項目や未対応の同期キューなど、安全に解釈できない端末データは黙って捨てず出力を中止する。

SDKの認証オブジェクト、localStorage、パスワード、アクセストークン、リフレッシュトークン、秘密鍵は収集しない。テーブル・端末型ごとの許可項目だけを構築し、認証属性が混入しても出力しない。

## オフラインと整合性の限界

サーバー全8テーブルを取得できた時だけ出力用キャッシュを更新する。一部だけ新しいデータと古いキャッシュを混ぜて「最新」としない。オフラインで過去キャッシュを使った場合は`cached`、取得歴がなければ`unavailable`にする。通常画面の変換済みキャッシュを、全8テーブルの最新スナップショットと偽って代用しない。

出力中はこのコントローラーの新しい同期を止め、実行中の同期が終わるのを待つ。端末データは同一トランザクションで取得する。ただしサーバー8テーブルは複数GETなので、別端末からの同時変更まで含む全体の同一時点は保証しない。

保存失敗中のメモリだけの入力は、出力対象に含まれるとは保証しない。UIとJSONの警告を確認する。ファイルは本人の端末へ直接ダウンロードし、サーバーやGitHubへ自動送信しない。個人の記録を含むため、自分で保管する。
